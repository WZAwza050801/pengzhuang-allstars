# 玩法默认值与物理说明

资料来源：`materials/pengzhuang_rebuild/`（2026-11-14 收到的复刻资料包）和更早的 `pengzhuang_research.html`，以及用户对原版的直接描述。
资料包明确说明：属性点到质量、初速度、曲率的公式，弧线的作用对象与手势，都没有恢复。下面的物理参数是按复刻手感目标自动校准的，不是原版数值。

标记：**R** = 原版文件或官方资料可查，**M** = 从原版图片量出，**U** = 用户描述原版，**B** = 本项目重建。

## 规则

| 项目 | 默认值 | 依据 |
|---|---|---|
| 人数与站位 | 5v5，默认阵型 2_2_1(A)：后卫居中，中场在场宽 20%/80%，前锋在 35%/65% | 横向位置 R（原版阵型表 10001）；三条线的纵深 B |
| 出手 | 轮流，每回合 1 次；按住己方球员反向拖动，松手弹射 | R（官方稿）；拖动画面 M（拉线在力度圈内、白点预测线） |
| 弧线 | 拉线时向左/右划弧带出弧线：拖动路径偏离直拉线的平均距离 ÷ 拉线长度 × 6 = 弧线值（−100%~+100%，按 5% 取整）；向射门方向的右侧划弧就往右拐。拉回球员身上重新计算。预测白点跟着弯，撞到任何物体后弧线消失 | 弧线存在 R、预测线会弯 M、作用于球员且用手势 U；换算比例 B |
| 进球 | 足球**整体**越过门线 | R（V1.3.3 更新日志） |
| 胜负 | 整场 3 分钟倒计时；先进 3 球直接获胜；时间到按比分判定，可平局。时间到时正在滚动的那一杆打完再结算 | 3 分钟与时间到判比分 U（截图 2:56 M）；“三球定胜负”R；最后一杆的处理 B。另有 100 手保险上限 |
| 开球 | 开场随机先手；进球后全部复位，失球方开球 | B |
| 回合计时 | 20 秒，超时视为跳过（计入手数） | B |
| 技能状态回合 | “离场 N 回合”“定住到下回合”按**该球员所属方的回合**倒数 | 时长 R；计数口径 B |
| 状态差 | 全属性 −30%，默认关闭 | R（V1.2.1） |
| 等级 | 默认统一 Lv5（技能 Lv2）；技能 Lv1/2/3 在球员 Lv1/4/7 解锁 | B |

## 场地（三套皮肤共用）

场宽固定 6.0 m，其余按原图比例换算：长 9.78 m（长宽比 1.63），球门开口 2.05 m（0.34 场宽），网深 0.4 m，禁区 2.65 × 1.32 m，无小禁区，中圈半径 1.0 m，球员半径 0.32 m（0.052 场宽），足球半径 0.12 m（0.02 场宽）。
来源：原版 1.5.5 球场底图 `Scenes_01.jpg` 的边墙内沿 956×1559 px，以及对战宣传图 `taptap_original_3.jpg`。门柱半径 0.07 m 为重建值。

四角是**动力弹簧**（U，原图四角可见弹簧装置 M）：斜边长 0.71 m（直角边 0.5 m）。
- 球员撞上弹簧：先按恢复系数 0.9 反弹，再沿弹簧法线额外加 2.2 m/s，弹出速度上限 7.6 m/s；接近速度低于 0.25 m/s 不触发。弹簧有压缩再弹出的动画和音效。
- 足球撞上弹簧：和普通墙完全一样，不加速。

电脑对战在这套原版比例下平均 5.1 手进一球（8 场，`npx tsx tools/goal-balance.ts 8`），一局大约 20 多手。

## 物理模型

- planck.js 1.4.2（Box2D 移植），120 Hz 固定步长，8/3 次迭代；所有物体固定旋转并开启 CCD。
- 滚动阻力每步：`v ← v/(1+c·dt) − k·dt`，低于停止速度即归零。指数项让力度与距离接近线性，常数项让收尾干净、不拖尾。
- 碰撞恢复系数按配对设定：球员-球员、球员-足球、球员-墙、足球-墙、球网（吸能）、门柱、球员-弹簧。
- 弧线（旋转模型）：出手后球员的朝向按固定角速度旋转（普通球员满弧线 0.33 rad/s，最多 103°），速度大小不变，所以不加能量。快的时候几乎走直线，越慢拐得越明显，形成“先直后拐”。满力满弧线横向偏 2.18 m，50% 力度偏 0.77 m。
- 服务器和客户端预测、电脑选球、校准、测试都调用同一个 `ShotRunner`；渲染只回放记录的帧，所以帧率不影响结果。
- 足球拖尾只是画面效果：最近 0.26 秒的位置画成半透明白色细带，速度越快越明显，低于 0.8 m/s 不显示。

## 球员差异只映射到 4 个因素

| 属性 | 物理量 | 范围 |
|---|---|---|
| 重量 | 质量倍率 | ×0.85 – ×1.25 |
| 力量 | 满力出手速度倍率 | ×0.92 – ×1.08 |
| 弧线 | 弧线角速度倍率 | ×0.6 – ×1.4 |
| 精准 | 瞄准虚线显示的长度比例 | 45% – 100% |
| 心理 | 状态模式下降低“状态差”概率（默认不影响比赛） | — |

## 手感反馈怎么对应参数

| 你的反馈 | 行为目标 | 主要参数 |
|---|---|---|
| “太飘” | 满力滑行变短、停得更快 | 提高 `disc.coulomb` / `disc.linDamp`，改 `calibrate.ts` 里 d100、t100 目标后重跑 |
| “撞起来太肉” | 碰撞后被撞者走得更远 | 提高 `restitution.discDisc`、`discBall` |
| “球太快” | 足球正撞后速度与滑行距离降低 | 提高 `ball.mass` 或 `ball.linDamp`，改 ballD 目标 |
| “弧线太弱/太强” | 满力 / 半力满弧线横向偏移 | 改 `curveLat`、`curveLatHalf` 目标后运行 `npx tsx tools/calibrate.ts --curve`（只调弧线，不动已确认的滑行和碰撞） |
| “弹簧太猛/太弱” | 弹出速度 | 直接改 `data/physics.json` 的 `spring.boost` |

改完运行 `npm run calibrate`（自动搜索并写回 `data/physics.json`）和 `npm run test:physics`。
