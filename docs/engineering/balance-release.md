# 平衡实验、灰度与回滚

`npm run balance:experiment` 以四个本机工作进程运行 500 个固定种子 × 交换先手，共 1000 场；再跑 5 组各 8 场敏感性实验。原始对局、阵容、等级、模式/数据/经济完整 hash、虚拟时钟及 AI 预算写入 `docs/productization/reports/balance-experiment.json`。工作进程只并行计算，按 seed/firstSide 合并，因此完成顺序不改变结果。

基线：easy AI、每次最多 2 个候选、不使用机器耗时决定搜索截断；每杆以录像时长加 2 秒虚拟思考时间推进比赛时钟。双方同阵容、同等级，seed 固定。该代理适合复现实验，不代表真人技巧分布、正式服务器墙钟对局或高难度 AI 的最终强度。敏感性包含 vmax ±5%、持有卡 Lv1/Lv10、AI 候选数 8；修改仅在隔离内存中，默认参数文件不变。

`npm run check:balance-experiment` 验证配置指纹、原始行、终局一致性、每 seed 恰好两场、统计重算及真实历史重放。`npm run check:balance-release` 在此基础上还要求至少 1000 场、无保险杆数作废、先手半分得分率的近似 95% 区间处于 45%–55%；不满足时返回非零。区间以独立 seed 对的均值估计，避免把同一 seed 两场当成互不相关样本。这只是平衡门槛，不代替完整发行验收。

当前初始实验未通过该放量门槛，见 BAL-07 报告。普通 `check` 检查实验可复查性，不把偏差较大伪装成损坏报告；发布命令单独阻止放量。不得删掉不利 seed、改摘要计数、替换预算却沿用旧 hash，或用未运行的数据勾选平衡通过。

`VersionedRegistry` 现在支持：

- `register`：校验包 hash、schema、协议区间及版本唯一性；不激活。
- `rollout(version, percent)`：按服务端生成的 cohort 稳定分桶，只影响新局；比例为 0–100 的整数。真实 MatchRoom 生成 UUID，忽略客户端自报 cohort。
- `activate(oldVersion)`：切换新局默认版本并清除灰度；旧局持有原有不可变快照。
- `disable(version)`：禁止新激活/灰度，仍保留显式历史读取；当前活跃版本必须先回滚再停用。
- `diffConfiguration`：以 JSON Pointer 记录完整值差异，数组整体替换，不隐藏索引迁移。

流程为：保留旧包 → 导入候选 → 校验完整配置指纹与候选对应的实验 → 发布检查成功 → 受控灰度新局 → 观察 → 全量激活；任何失败先激活已验证旧版、清除灰度，再停用坏版。既有对局不改版本；不能可靠恢复时明确作废，不重算一个“差不多”的结果。

本次真实运行时接线覆盖现有 physics 版本注册表；经济也复用同一注册表能力，但业务账本热更仍待 DAT/OPS 接线。`config/physics-archive/phys-4.json` 保存 hash 包，`config/mode-archive/modes-1.json` 保存模式定义；已有经济档案保留。归档命令发现同版本不同内容会拒绝覆盖。新增模式档案要显式加入静态加载表，以保证浏览器打包和历史摘要可核对。

灰度/停用指针是本进程控制状态，跨重启的发布状态、权限审计与运营控制由 OPS/ADM 接入。没有增加匿名远程配置修改入口。当前灰度默认关闭；实验门槛失败期间未启用任何候选版本。
