# 持有卡、阵容与升级页面（UI-04）

入口 `/lineup`，懒加载 `client/src/inventory/route.tsx`。页面状态和请求放在 `use-editor.ts`，阵容、持有卡、详情和旧偏好分别呈现。复用 DAT-02/03/04、现有图集渲染/加载器、BAL 属性/技能规则及 UI tokens；没有另一套物理或经济计算。

## 服务与读数

`GET /auth/options` 的 `inventoryEnabled` 只在会话、云数据、阵容和资产服务实际挂载时开启；缺字段按 false 兼容。它决定页面入口，不代替业务鉴权。匿名访问回登录，成功回阵容页；退出未确认继续原账号流程。按 userId/sessionId 重建页面，旧账号的异步结果不能落入新账号视图。

`WebAccountClient` 增加本人持有卡、阵容、钱包、报价/升级和保存方法，全部校验请求/响应。库存读取并行加载卡、预设、钱包；逐页读完而不是把首 50 张当全量。重复卡 UUID/游标或超过 100 页判无效响应，不无限读取。UI 每页只渲染 12 张图集卡，支持姓名、职业、可用/停用/资料待更新筛选。图集由 `WebAssetScene` 校验、解码并在离页释放；文字仍能在卡面未加载时使用，不伪造持有权。

姓名/职业/原始属性和技能资料来自已有数据；持有等级、状态和余额来自服务端。属性/技能仅在客户端数据版本和 manifest 一致时展示，未知定义要求更新客户端，不能当成可用卡保存或升级。未实现的源技能明确提示正式排位/成长不可用。正式参赛仍由 DAT-03/NET 按模式重验，不把通用阵容保存当参赛票据。

## 五槽与保存

点选槽位，再点持有卡放入；选中已在阵容中的卡会交换位置。五槽完整、不重复、卡可用才可保存；清空后提示未保存。职业仍只是推荐，保留 DC/CM/CM/ST/ST 的顺序，不新增职业硬限制。浏览器支持键盘进入槽和卡，详情有焦点与返回列表入口。预设切换在草稿脏时禁用，用户可保存或显式还原；不静默丢弃草稿。

PUT 仅提交 `{ownedCardIds,expectedRevision}`。成功再更新本地基线；冲突读取服务器阵容并并列说明，原草稿保留。用户选择采用服务器阵容，或明确保留草稿并使用新 revision 后再次保存。失败/重试不自动用新 revision 覆盖他人的修改。

响应丢失时 GET 核对原目标；版本增加且内容相同即确认保存。无法读取结果则锁住原保存草稿，提供“确认保存结果”，只重新 GET，不盲发第二个 PUT。普通刷新/焦点恢复保留脏草稿，已变更的服务器版本进入冲突提示。DAT-05 旧偏好仅在仍合法持有时可显式采用为当前草稿，随后仍需保存，没有重发初始资产。

## 报价和升级

详情按卡 UUID/版本取服务端当前报价，显示成本与下一等级；价格不由前端提交。金额经严格十进制字符串和 BigInt 展示/比较。余额不足禁用新升级；读取后被并发扣款仍由服务器拒绝，刷新真实余额，不乐观扣款或增加等级。最高 10 级与停用/未知卡有明确状态。

`UpgradeIntentModel` 在发请求前把版本化意图写入本标签页 `sessionStorage`，键按 userId 隔离，最多 2048 字符。内容只有 userId、ownedCardId、UUID operationId、卡 revision、经济版本，没有密码、token、价格或客户端最终余额。读取和结构校验失败有提示；无法保存重试记录时不发送扣款请求。

同步锁防双击。网络/无效响应/临时服务故障保留原 key 和 body；刷新页面后用户可显式“确认上次升级结果”，不会自动产生新意图。权限、限流或账号切换拒绝也不能证明此前未提交，保留记录待原账号确认；确定的业务拒绝释放意图并提示重新报价。成功返回历史回执后再次读取当前库存，不能把旧回执中的余额当当前余额。清理记录失败明确区分“已成功”和本机清理失败；迟到响应只清自己的 key，不能删除重挂载页面的新操作。

本地意图不是可信资产。即使修改 sessionStorage，服务端仍验证实际身份、所有权、状态、revision、当前价格及幂等载荷，不会导入本地等级/货币。

## 跨账号和 CSRF

库存/阵容/资产接口支持可选 `X-Account-Id`；本 Web 页面总是发送。服务器身份仍来自有效会话，该头只拒绝切换账号前的遗留意图。不匹配返回 HTTP 409 / `ACCOUNT_CHANGED`，区别于业务 revision 冲突，不清掉原账号的未确认升级。大厅摘要和旧导入原有三个接口继续要求此头。未提供头的既有客户端保留原授权语义。

客户端在验证到新 sessionId 时丢弃旧 CSRF 缓存；旧会话迟到的 CSRF 请求不能覆盖新缓存。403 会使当前代缓存失效，但不会自动重放写请求。恢复原账号后才能确认它的升级记录；新账号使用独立意图和 CSRF，不继承余额或草稿。

## 验证与边界

真实数据库/浏览器验证登录回跳、保存/冲突/未知结果、扣款与幂等、跨账号、越权/禁用、分页/筛选、旧偏好和存储拒绝；详见 [UI-04 报告](../productization/reports/UI-04.md)。空库存与客户端未知定义使用明确的 HTTP 响应注入测试，未将这些注入数据声称为生产持有资产。

无资产 schema、外部依赖、价格/物理参数变更，无远端运行。发布授权/设备/平台和平衡门槛保持；正式对战入口由 NET/UI-05 后续接入。回滚本提交的页面/客户端改动不撤回已经成功的数据库升级；任何资产纠正仍须追加受控流水。
