# 数据对账与受控修复（DAT-06）

此工具供具有数据库维护凭据的操作者使用，没有玩家 HTTP 路由。入口 `tools/data-maintenance.ts`；验收证据见 [DAT-06 报告](../productization/reports/DAT-06.md)。

对账在 PostgreSQL REPEATABLE READ / READ ONLY 事务内读取，不初始化账号、不发奖、不改待处理任务；金额使用 BigInt/十进制字符串。每批是独立数据库快照，跨批不声称全库同一时刻。按用户/比赛分页，孤立引用独立检查，设置查询与锁等待上限；超时必须报告失败，不能报成健康。

钱包是账本的投影。若原账本可验证为 300 而投影损坏为 400，恢复投影到 300 时追加 delta=0 的纠正流水，记录修复前后和 -100 投影差额。不能使用普通扣除 -100 再改变账本总额，否则总账会错误变成 200。原账本不修改、不删除；账本自身冲突、时间顺序无法验证或引用缺失时不自动猜测，保留证据转人工。

独立的业务补偿是另一类操作：操作者审核原因、问题编号、对象、明确的金币/碎片调整额和当前快照；执行复用可信 grant/debit 事务并追加正常资产流水。它不修改原比赛胜负或伪造原奖励回执，也不能用来掩盖未解决的源数据冲突。相同意图可重放原回执，相同问题/对象换 key 不能重复补偿。

结算重试只重新排入已存在的待处理结果/事件，验证冻结配置和载荷 hash，沿用原 matchId 与去重来源。已结算结果、权威冲突、缺失持久结果拒绝重排；不会重写胜负或自己造一份新奖励。真正处理仍由可靠结算消费者完成，排名端口缺失仍明确等待 MM-02。

修复计划版本化、绑定数据库名和状态指纹，显式提供审核过的 SHA-256 才执行；指纹保证意图/陈旧检测，不是身份认证或审批签名。身份边界是实际数据库凭据，回执记录数据库会话用户/有效角色；未来 ADM 的 RBAC/审批页面另行实现，不能拿 CLI 文本自称管理员。所有写入、纠正流水、回执、outbox 必须同事务，异常回滚，并保留已有完整事务的有界重试和锁顺序。

只读快照依据 [PostgreSQL 17 事务隔离](https://www.postgresql.org/docs/17/transaction-iso.html)；数据库端指纹使用内置 [二进制字符串 SHA-256/编码函数](https://www.postgresql.org/docs/17/functions-binarystring.html)，无需扩展；短期互斥使用随事务结束释放的 [事务级 advisory lock](https://www.postgresql.org/docs/17/explicit-locking.html)。

维护样例必须使用测试工厂。隔离运行器在临时数据库写入每轮随机标记；工厂确认数据库名和该标记与 PG_TEST_RUN_ID 一致后才允许迁移或写入，原生/容器运行器使用同一边界。不得把生产身份、密钥、备份内容或真实用户报告放入 Git，不在生产注入异常。

## 命令与退出码

先部署 expand 迁移 `202611180016_data_repairs.mjs`。检查命令不会自动迁移。通过受控会话向 `MAINTENANCE_DATABASE_URL` 注入连接配置；检查使用只读凭据，执行修复使用经过授权的维护凭据。命令参数不接受数据库 URL、管理员角色、任意 SQL 或改写胜负的字段。不要在 shell 历史粘贴凭据；下面命令假定环境已经配置。

```powershell
# 单个对象；UUID 换成受理工单中的内部标识
npm run data:maintenance -- audit-user --user 00000000-0000-4000-8000-000000000001
npm run data:maintenance -- audit-match --match 00000000-0000-4000-8000-000000000002
# 默认每页20，最多100；将输出 nextCursor 作为下一批 --after
npm run data:maintenance -- audit-users --limit 20
npm run data:maintenance -- audit-matches --limit 20
npm run data:maintenance -- audit-orphans --limit 20

# 先生成不可覆盖的计划文件。仅生成计划不会写数据库。
npm run data:maintenance -- prepare --kind restore-wallet --user 00000000-0000-4000-8000-000000000001 --currency coins --case SUPPORT-123 --reason "恢复已验证账本投影" --out work/repair-reviewed.json
# 核对文件的对象、原因、数据库、指纹、前后值和输出摘要，保存审核过的SHA。
# 实际执行时将下面变量设为该审核值，不要临时从可能被改写的文件重新读取。
npm run data:maintenance -- apply --file work/repair-reviewed.json --sha256 $reviewedSha256
```

`prepare --kind compensate` 同时要求 `--user`、`--currency`、非零有符号十进制字符串 `--delta`；只允许 coins/fragments，禁止透支或 int64 溢出。`prepare --kind retry-settlement` 要求 `--match`，不接受 user/currency/delta；仅恢复已有结算意图。所有计划要求工单号、原因与输出路径。同种操作/同工单/同目标只能执行一次，工单号标准化为大写；合法的后续独立纠正必须有新的工单和重新核验的状态。

`node --import tsx tools/data-maintenance.ts ...` 直接调用时 stdout 是单份 JSON。通过 npm 调用另有 npm 的命令提示。检查退出码：0 为本次对象/页面未发现已覆盖的不变量异常，2 为发现异常，1 为参数、权限、连接、锁/查询超时或内部错误。分页结果不代表整个数据库健康；连续检查会跨多个快照，并发插入在游标之前的数据需下一轮重扫。孤立检查输出每类总数和有界样本；超时不输出“零异常”。不要忽略退出码1，也不要将空页当作已经检查所有对象。

计划最大64KiB，读取时检查普通文件与大小；生成使用独占创建，不覆盖旧文件。修改计划内容、审核摘要不符、目标状态变化或数据库名变化都会拒绝执行。数据库提交成功但输出丢失时，以相同文件和审核值重试，返回原回执；不能临时换工单/key。回执重放不回退之后的正常资产操作，不把已处理的结算事件再次重排。SHA用于确认具体意图，不提供双人审批；工单审批和密钥分发由现有组织流程承担，ADM-04 接入真正的后台权限与审批。

## 异常处置与验收顺序

1. 使用只读凭据取受影响用户、比赛与孤立引用报告，记录内部ID、数据库、快照和错误码；报告受访问控制，不含账号密码、身份载荷或原始恢复快照。先核对异常范围，避免为每个症状分别补偿。
2. 对投影损坏，只有账本顺序、每步余额和业务回执可验证时才生成 restore-wallet。对单独获批的业务调整生成 compensate。两者都不能修改历史资产或奖励回执；账本本身损坏、来源不明或同币种时间顺序存在歧义时停止该项自动修复，保留证据，转专项前向修复方案。
3. 对失败结算，先修复依赖故障；核对原结果、冻结配置、两个参与者、outbox hash，确认没有已提交的半份奖励，再生成 retry-settlement。消费者继续使用原来源去重；真实排名端口未就绪不能靠本工具伪造排名成功。
4. 由有维护权限的操作者审阅计划和SHA，再执行同一计划。修复使用用户→钱包锁，结算重排遵循消费者的 outbox→match→outcome 锁顺序；工单/计划事务锁避免并发重复。资产变化、追加流水、修复回执及 `data.repaired` 事件同时提交；单条失败全部回滚，死锁/序列化冲突最多重试三次。查询/锁超时后重新检查现场，不持续忙等。
5. 再次只读检查，并关联修复回执、纠正流水及结算原回执。并发业务导致计划过期时重新取证、重新审核，不能修改旧指纹绕过。原始奖励异常在一般补偿后仍可能被报告，必须保留并交接，不能宣称所有异常已自动治愈。
6. 需要撤销补偿时按新工单追加反向纠正，重新校验余额和状态；禁止删除旧回执或修改原流水。回退代码不回退资产，迁移 down 只供隔离环境且会丢失修复证据，不用于生产“撤销修复”。

## 保留与匿名化

| 数据 | 当前保留/清理边界 |
|---|---|
| 账本、资产操作、比赛结果/奖励、初始化与修复回执 | 追加保留；当前工具不设TTL、不提供删改命令。工单去重键、账本来源与奖励引用需持续可核验。归档前必须设计等价查询/去重与恢复校验并经 OPS/REL 评审，不能单独清理旧 outbox 后让引用失效。 |
| 已处理/待处理的结算事件、冻结配置、待恢复比赛 | 保留原意图和配置；本工具不清理。待处理/失败事件不能作为“旧垃圾”删除；重启保留与过期局策略由 NET-05 实现，备份恢复由 OPS-03/QA-05 演练。 |
| 账号直接标识与自定义资料 | 沿用 [ACC-06 生命周期](account-lifecycle.md) 已实现的宽限期、撤销与擦除流程。删除邮箱/凭据/可识别资料，保留内部 UUID 和资产外键；这是去除直接标识，不宣称完全不可关联匿名化。 |
| 脱敏诊断报告与本地计划 | 仅存在受控工作区，禁止进 Git。工单结案后由操作者清理临时副本；持久审计在数据库回执，非本地文件。未结工单保留所需证据；没有后台自动清理，也没有隐含“永久保存全部报告”的承诺。 |
| 隔离 fixtures | 仅测试数据，运行器结束后停止实例并清理临时目录；失败清理必须报错。随机标记用于防误写，不代替生产权限隔离。 |
| 备份、第三方投递与历史外部日志 | 本工具无删除能力。生产启用前由 REL-02/OPS 给出具体保留期限、备份到期与恢复后重新执行擦除的方案；不把工程默认宽限期视为渠道保留政策。 |

修复原因只写工单编号和业务说明，禁止粘贴邮箱、手机号、token、数据库连接串或原始用户提交。维护凭据需分离运行账号与迁移身份；追加触发器能阻止普通 UPDATE/DELETE，但数据库所有者/超级用户能改DDL，不能称为对超级用户防篡改。此任务没有修改任何生产角色或权限。
