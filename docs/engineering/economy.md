# 非付费成长经济（BAL-05）

当前配置 `data/economy.json` 为 `economy-2`，属于可调整的工程默认方案，不是商业定价或真人平衡结论。支付关闭。原参考表 reward / cupMatchReward / shop_gold / shop_contract 的 77 / 19 / 3 / 3 行及文件 hash 记录于 `docs/productization/reports/economy.json`，不把旧 Crystal 商店价格导入新方案。

## 卡组、货币与成本

- 单用户同定义一张卡，等级 1–10；重复获得转碎片，不生成重复实例，升级不消耗重复卡。
- 初始 `p07,p06,p08,p01,p02` 对齐现有默认阵容，授予 300 金币、0 碎片。`starter-v1` 是稳定的一次性授予标识，配置升级不得自动重发。
- 新账号经济卡池仅包含技能已实现或无技能的 46 个定义；71 个技能未实现定义暂不进入授予/合成池。练习数据仍保留全部 117 个定义，不虚构缺失技能。
- 升级公式为 `roundHalfUp(100 × (3/2)^(L-1))`；使用 BigInt 有理数计算，逐级成本为 `100,150,225,338,506,759,1139,1709,2563`，单卡 1→10 合计 7489。金额上限为有符号 int64 最大值，负余额和溢出均拒绝。
- 原数据稀有度 1/2/3/4/5/9 对应重复转化 5/10/15/30/50/100 碎片；缺原稀有度的重建卡使用明确的 quality 映射。合成未持有卡消耗其转化量的 10 倍，已持有/不可用/余额不足先拒绝再扣款。
- 接口金额为十进制字符串，域内为 BigInt，禁止 Number 浮点货币。客户端展示服务端报价，不提交价格、最终等级或余额。

## 产出与活动进度

正式可信比赛的胜/平/负金币为 50/35/20；每天最多 300，达到上限前可部分发放。每位用户至少 2 次动作、比赛至少 30 秒且正常完成才符合资格。练习、弃赛、认输、服务器故障不发此项奖励；模式是否允许产出由服务端配置决定，客户端不能自报。

每天边界采用服务端时间 UTC+8。奖励归属日使用可信 outcome 的完成时间，不使用迟到请求的处理时间。每日累计以用户/业务日/货币为域，不因切换 economyVersion 重置；降低上限后已有累计超过上限时新增为零。修改日界线需要迁移规则，不能让相同比赛跨日重领。

每累计 3 场合格比赛获得一张卡，每天最多 1 张。`economy-2` 的进度跨日保留，成功领取后归零，当天领过后额外场次不累计下一张。发卡按稳定排序的合格卡池及服务端成功领取序号轮换，重复走碎片路径；序号必须持久化。`config/economy-archive/economy-1.json` 保存了此前“必须同日完成 3 场”的未发布草案：模拟揭示每天 1 场用户长期拿不到新卡，因此修订。此草案不是已经验证的生产回滚目标。

## 权威与事务接入要求

`packages/game-core/src/economy.ts` 提供不可变纯规则；`tools/economy-simulation.ts` 的 receipt/账本仅为单进程模拟。DAT-04 已完成真实账户升级、合成、受信授予/扣除、事务幂等与账本查询，见 [资产操作](asset-operations.md)；正式比赛资格、每日进度和结算由 NET/LIV 接入。

DAT-04 在同一数据库事务内锁定用户、钱包和卡，校验持有权/revision，执行报价与扣款/发卡，追加流水，写幂等结果和 outbox，失败全部回滚。初始授予唯一键使用 `(userId, account.starter, starter-v1)`，不随配置版本重发。后续 NET/LIV 必须将 matchId/userId/rewardType 唯一奖励记录、参与卡每日领取/累计进度/成功序号与资产端口放在同一事务；当前资产端口不代替这些资格校验。数据库回执比较载荷 hash，同键异载荷冲突。

升级和合成的 `expectedEconomyVersion` 对比**当前生效价格版本**，拒绝陈旧报价。奖励则由可信 outcome 绑定的历史 economyVersion 与 GameData 计算，并沿用唯一奖励记录。两类版本不能混用，不允许请求旧版低价升级。报价/升级/合成/账本 HTTP 控制器已挂载；内部授予没有玩家写入口。

服务端加载使用 `createBundledEconomyConfiguration()`，校验 schema、引用、GameData 版本、policy hash 及 pricing hash。pricing hash 包含卡的可用状态和稀有度衍生报价，修改这些值也必须提升 economyVersion。同版本改内容时 `balance:economy` 与加载器均拒绝。单局持有冻结配置；热更新/回滚与保留策略在 BAL-07 完成。

## 可复现实验

运行 `npm run check:economy` 复核已提交报告；有意修改参数、版本并审阅差异后用 `npm run balance:economy` 生成。`npm run test:balance` 验证经济及已有数值/技能边界。

固定 seed42，胜/平/负概率 .5/.1/.4，每场均假设可信、正常结束、每人 3 次动作、90 秒；优先均衡升级初始五卡，再合成最低成本未持有卡。结果是策略预测，不代表真人行为、正式比赛收益或上线承诺。
