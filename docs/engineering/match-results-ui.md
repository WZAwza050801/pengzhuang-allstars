# 本人结果页与回局交互（UI-06）

账号比赛继续复用 NET-04 的权威结果和实际奖励凭证。比赛结束画面及连接顶栏提供“查看结算”，路由 `/result/:matchId?mode=friend` 在新页面或刷新后按同一 matchId 查询。大厅、已结束的回局面板及结果页进入 `/results` 本人比赛记录，默认 20 条，游标加载更早结果。查询参数的 mode 只是导航提示，显示的模式、胜负、比分、原因和奖励来自本人服务端结果。

## 状态与操作

| 已确认的服务端状态 | 页面行为 |
|---|---|
| pending / recorded=false | 结果等待保存，不展示零奖励或奖励流水；保存确认前不提供新一局操作。 |
| recorded | 明确结果已保存、奖励等待入账；有界自动查询及手动重查。 |
| settled | 展示实际奖励凭证，零奖励也必须来自已完成凭证；仅在这个状态读取关联流水。 |
| failed | 保留已有结果并显示等待处理，重查只读，不调用发奖、补偿或管理重试。 |
| 失败 / 离线 | 保留本会话已确认的信息，明确尚未更新；无已确认结果时提示联网后查询，不合成比分或奖励。 |
| 已结束回局 / 外人访问 | 结束的原房间不能重入，给出本人记录入口；外人结果不展示。 |

好友赛显示不计排位积分和无正式奖励；growth/ranked 尚未在生产开放，也没有虚构积分零变更。已有这些模式的记录可只读查看，但积分仍显示未确认，不提供新对局入口。真实排名记录须由 MM-02 提供后接入。

“再来一局”进入新的好友房设置，重新读取当前持有阵容；用户再创建房间、邀请好友并准备。导航本身不分配房间或修改结果；房间创建复用既有单次提交防护。旧 matchId、outcome、账本和奖励不会因新一局被覆盖或再次执行。

## 查询与隐私

`MatchResultModel` 只依赖读取结果与流水的端口。同一视图的并发读取共用请求，销毁或身份变化后的迟到响应不写缓存、不更新页面。结果从已保存/已结算状态不能被较旧响应降级；流水需精确匹配奖励凭证的 ID 集合、来源、原因及金币/碎片合计，查询失败不修改实际奖励。

`ResultCache` 是按 userId/sessionId 隔离的有界内存副本，最多 32 场。退出、换号、账号查询拒绝及 Provider 销毁时立即清除；不写 localStorage、IndexedDB 或磁盘，不保存凭据。页面刷新在确认当前登录账号后重新查原结果。离线可在仍运行的会话中查看此前确认的结果并在记录/结果页间导航；未联网确认过账号、未读取过的结果及冷启动离线不声称可恢复，页面明确提示联网查询。

自动查询仅在前台、在线、身份仍有效且结果为 pending/recorded 时执行，最多 8 次退避查询、间隔最多 15 秒；恢复网络、回到前台/焦点可重新核对，手动查询始终不触发结算。组件清理移除定时器和事件监听。主路径为轻量页面，保持练习赛与比赛资源按原方式分开加载。

新增 `GET /api/v1/matches/:id/ledger`，带必需 `X-Account-Id` 与活跃会话核验。只返回本人的该场已提交奖励所关联的 `match.reward` 流水，响应包含 userId/matchId 供客户端核对，不显示这些内部标识到普通页面；外人 404、尚未结算 409、无效查询 400、退出/封禁 401。成功响应 no-store，支持真实 OPTIONS，客户端无法用写接口领取或重放奖励。

流水读取在同一数据库事务中验证参赛者、已结算结果、奖励凭证与账本条目，核对条数和金额；无流水必须对应真实的零货币凭证。HTTP 合同见 [contracts.openapi.json](contracts.openapi.json)。生产未新增表或迁移，未改动已确认的物理、模式、等级和经济数值。

## 验证边界

UI 验收使用真实数据库与双浏览器，覆盖延迟消费、刷新、离线后原结果、丢失终局广播、结束后原房间拒绝进入、重复查询/新局创建、实际正数奖励及流水、查询失败不归零、23 场分页、320/768/1440 与大字号/键盘、换号时迟到响应隔离。正数奖励/历史记录的准备夹具通过 NET-04 真实资产事务与测试 SQL 排名事务标记生成；该标记没有生产绑定，不是 Elo 实现或网络物理验证。真实好友赛结束仍通过双方实际房间操作验收。

浏览器截图不替代真机，服务端运行局重启接管仍属 NET-05，正式排名属 MM-02，管理重试和补偿属 ADM-03/DAT-06。具体环境、命令和最终结果见 [UI-06 报告](../productization/reports/UI-06.md)。
