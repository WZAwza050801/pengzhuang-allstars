# 真实账号大厅（UI-03）

大厅保留原 Web 壳、练习 Canvas Host 和五主导航，连接 ACC/DAT 的真实账号数据。相关入口为 `webScreens.tsx`、`lobby-account.tsx`、`lobby-context.tsx`、`PlayerData.lobby` 与 `public-lobby.ts`。

## 数据来源

| API（前缀 `/api/v1`） | 行为 |
|---|---|
| `GET /me` | 恢复真实用户/会话与资料；复用原账号状态模型、Cookie、刷新策略。 |
| `GET /me/lobby` | 当前资料、两个钱包、持有卡数量、初始阵容可用卡数/版本；`X-Account-Id` 必须与已验证会话一致。 |
| `GET /config/manifest` | 支持协议、当前 GameData 版本、四种服务端 ModeRules、可用模式及大厅维护状态。 |
| `GET /announcements` | 版本化、已发布且未过期的公告，按发布时间倒序。 |

账号摘要在用户/会话锁内读取并复用 DAT-02 初始化，资产写服务使用同一用户锁，所以读到一致的本人钱包/卡/初始阵容状态。卡数来自数据库；可用槽数按当前 active 卡计算，禁用卡不会继续显示五人就绪。摘要不返回 token、其他用户数据或玩家可写角色。客户端验证 DTO 和回包 userId，账号切换后的旧请求不能读作新账号结果。

钱包/经验以十进制字符串读取，用 BigInt 格式化千位分隔符，超过 2^53 仍完整显示。加载显示“余额尚未确认”，失败隐藏未确认余额并提供重试；缺钱包显示“尚未建立”，不填假 0。资料和阵容为空时有明确提示。真实余额为 0 则如实显示 0。旧 `pz_profile`/卡等级不参与大厅账户资产。

登录从大厅发起时保留回大厅意图；原账号页/受保护页面回跳继续生效。账号页提供真实设备/绑定/注销和 DAT-05 导入入口。刷新大厅同时重新确认会话、个人摘要和公开配置；焦点、重新联网、可见性变化触发失效刷新，没有固定高频轮询。请求按账号/会话隔离，卸载/新请求丢弃旧异步结果；401 撤下私人数据并回到登录入口。退出未确认时沿用原重试流程。

## 模式、公告和异常状态

四种规则从 `rulesForMode` 生成，不复制另一份物理/等级/时钟配置。用户可选择查看规则，刷新/失败重试保留选择。目前只开放练习；正式房间、排位/成长赛事和奖励仍等待 NET/UI-05/MM，不用配置元数据冒充可玩入口。

公告来源为 `config/lobby.json`，以严格 schema 校验并冻结；当前 `lobby-1` 无公告，界面显示“暂无公告”。只返回服务端墙上时钟判断已发布且未过期的内容，精度不同的 ISO 时间按实际时刻排序。标题和正文以 React 文本渲染，不插入 HTML，不接任意外部链接。未来 ADM 可通过同类型只读端口提供发布结果；当前不是管理后台发布功能。

公开配置/公告可匿名读取，不依赖数据库；两者 no-store，不暴露 DSN、密钥或邮件配置。公开读取失败可以单独重试，不显示虚构公告。协议不在支持列表时提示“客户端版本过旧”并提供刷新；`LOBBY_MAINTENANCE=true` 显示维护状态并由导航阻止远程入口。该开关是大厅呈现/导航状态；停新房间、drain、readiness 与全局维护执行仍由 NET/OPS 接入，不能据此宣称已完成运维维护流程。

离线时保留状态说明。已经载入的练习可继续使用；尚未载入练习模块时按钮禁用并提示先联网进入一次，离线直接访问练习路由也有返回入口，避免动态模块请求失败导致空白。没有承诺清空浏览器缓存后仍可冷启动或完成 PWA 离线发行。

## 验收与交接

真实 SMTP 登录回大厅、受信资产授予后刷新、大整数、状态变化、会话封禁和公开运行时接口均验证。慢请求/503/空 DTO/不兼容协议为明确的浏览器故障注入；真实离线使用 Chromium 网络切换。账号切换和 X-Account-Id 不构成新的授权方式。详细结果见 [UI-03 报告](../productization/reports/UI-03.md)。

浏览器验收工具可设置 `WEB_ACCEPTANCE_REPORT_DIR`，把本轮截图/JSON 写入独立目录；默认路径保持原有工作流。无新依赖或资产迁移，玩法/经济参数未改，生产和测试客户端的调试隔离保持。
