# 旧本地偏好导入（DAT-05）

账号页“旧本地存档”提供检查、预览、确认导入、查询已导入结果及在本机使用设置。不会自动读取后覆盖账号资料。入口为 `client/src/accounts/local-import.tsx`，解析为 `packages/client-model/src/local-import.ts`，服务为 `server/accounts/local-import.ts`。

## 兼容范围

| 旧键 | 导入行为 |
|---|---|
| `pz_nick` | 复用昵称验证，NFC 归一化/去首尾空白；保存为昵称草稿。 |
| `pz_skin` | 仅允许当前 FIELD_SKINS 中的 ID，保存外观偏好。 |
| `pz_muted` | 仅 `0`/`1` 转为布尔值。 |
| `pz_lineups` | 旧 `{active,sets}`，最多三套五人不重复定义 ID；客户端验证已知定义，服务端转换为本人当前持有且 active 的卡 UUID，保持槽顺序。 |
| `pz_profile`、`pz_card_level`、`pz_server`、`pz_last_code` 及其他键 | 不复制、不上传；不作为货币、等级、卡牌、权限、凭据或服务器配置来源。 |

只读取上述四个允许的偏好键，每项最多 20000 字符。JSON 损坏、未知球员、错误音量/皮肤/昵称、存储权限失败分别给固定提示，合法独立项仍可导入；没有合法内容时不提交标记。保留所有旧键及旧练习兼容读取；没有删除旧存档或将旧练习等级变成账号资产。

未持有、未知、禁用卡的整套偏好在服务器跳过并记录 slot，不能拼接不完整阵容。active 指向被跳过套组时归 null。昵称仅为草稿，偏好仅为建议，不自动修改云资料、正式阵容、卡等级或余额。后续 UI-03/04 使用草稿时仍需用户确认，正式阵容保存/参赛仍经过 DAT-03 的实时校验；导入成功不是永久参赛许可。

已保存的声音/球场可由用户明确点击应用到本机，影响下一场练习；设备设置仍属于本机，不在切换账号时自动重写。现有声音层允许内存工作而浏览器存储不可用，导入面板会检查持久化失败并提示重试。

## API 与一次性标记

| 路径（前缀 `/api/v1`） | 契约 |
|---|---|
| `GET /me/local-import` | 返回 `{receipt:null}` 或当前账号的已导入回执。 |
| `POST /me/local-import` | 严格 `LocalImportCommandSchema`，version 为 `pz-local-v1`，settings、nicknameDraft、lineups、activeLineup 均有界；返回服务端过滤后的回执。 |

两个请求均要求有效会话及 `X-Account-Id` 等于服务端已验证 Principal 的 userId。这个头只用于拒绝账号切换时遗留的请求，不能选择其他用户；不匹配 409，未登录/封禁 401。写请求沿用 Origin/CSRF 校验。组件按账号重挂载，卸载后丢弃异步 UI 结果。响应/请求均由共享 schema 校验，不存 access/refresh/token。

`account_local_imports` 以 userId 为主键，保存规范化命令 SHA256 和服务端结果，构成账号级一次性标记。用户/会话锁后检查原回执，同载荷重放原结果，不同载荷 409，重新检查即可展示已导入结果。不存在客户端可以清除后重领的奖励标记。

首次 POST 如遇未初始化的合法老账号，只调用 DAT-02 的 `starter-v1` 初始化；这和导入标记在同一事务。卡偏好查询与保存也在此事务，失败全部回滚。多实例/并发重复只保留一行标记；响应丢失时保留原预览重试或查询回执，不能将失败当作重新发放新手资产。数据库死锁/序列化重试复用 DAT-04 的完整事务有界重试，无网络副作用。
