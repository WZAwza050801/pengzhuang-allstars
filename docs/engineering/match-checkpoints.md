# 账号局快照与服务重启接管（NET-05）

账号房沿用 shared 物理、协议2、NET-03本人席位和NET-04结算。运行时现已接入初始快照、已接受出手、时钟/连接窗口、启动接管和缓存回收；游客format1仍走独立恢复路径。验收证据见 [NET-05报告](../productization/reports/NET-05.md)。

## 数据与确认边界

迁移 `202611180017_match_checkpoints.mjs` 增加追加式 `match_checkpoints` 与可变 `match_recovery_heads`。快照含format/engine、原matchId/房间码、完整局面/RNG、有序成功出手回执、双方冻结持有卡、配置hash和剩余时钟；配置本体复用NET-04不可变归档。不存登录会话、票据或游客seatToken；恢复时仍需登录并换取原席位的新票据。

开局在同一事务内保存参赛者、冻结配置和初始快照，提交后才广播。非终局出手在局面副本上计算，保存成功才安装内存状态、广播和确认。SQL失败保留同一待写候选，原shotId重试不会重新计算或增加序号；同ID异载荷仍冲突。计时与连接窗口进入原房间串行命令流。快照按ordinal追加并校验前缀、revision/seq、冻结席位、原配置和时钟预算，禁止原地UPDATE。

数据库等待与终局日志发布使用异步入口，数据库行锁以房间head隔离；另一局和Node事件循环可以继续。每房串行与有界重试保留，不为等待存储发送提前成功。终局日志发布队列最多128项、受保护日志默认最多1024项，每条最多256KiB；这是单进程边界。既有结果日志的后台重试/清理仍有同步文件操作，物理模拟与实际多房p95/worker方案留NET-06，不能据此宣称完成生产容量验收。

## 单一持有者与终局优先

数据库时钟租期默认15秒，运行时ownerId和递增epoch约束写入；过期续约不能复活旧持有者。房间从请求开始时刻保守计算本地有效期，失权停止权威服务。丢失SQL响应后，同候选/旧指针可返回已提交回执，换载荷不能覆盖。正常关闭释放持有权；强制结束后新进程等待实际租期届满，启动扫描每秒重试，每页最多100个head。

`pending-outcomes/account-recovery/storage.json` 保存持久日志域UUID，head绑定同一UUID。必须保留原数据库和原日志卷；只有数据库、没有原卷的实例计为foreign并拒绝接管，避免从旧运行快照复活仅在原卷落盘的终局。复制生产卷、路由/跨实例准入和备份恢复由OPS验收；不能通过删除或随意改写storage.json绕过。

终局首先保存以下任一来源，才允许交给NET-04并对客户端确认：

- 持有权约束下提交的SQL终局快照。
- 同一日志域内、在保守有效期内发布并同步的终局文件；文件绑定原head序号/hash、owner/epoch及完整终局快照。

SQL和文件并行尝试。SQL暂不可达时保留可靠文件兜底；文件不可写时仍可使用SQL。两者均失败则保持冻结候选、无成功出手回执/终局包，按同一载荷有界重试。没有可靠副本时，不保证进程结束后保留尚未确认的候选。

新持有者先检查受保护终局，再安装运行房间。文件与head基线一致时保存终局并沿原结果/奖励管线处理，不重新开放旧局；SQL终局本身也可驱动重试。已记录原结果按hash去重，只有确认outcome已提交才删除对应受保护文件。基线早于已推进head的迟到文件移入quarantine；hash/配置/来源冲突保留证据并停止该局自动恢复。原NET-04 format1日志与结果唯一性保持兼容，新增生产发布入口为异步；没有新玩家结果/发奖API。

发布使用独占临时文件、文件fsync和不覆盖的硬链接，非Windows还同步目录。Windows验收覆盖进程崩溃，不声称已验证机器断电或存储硬件故障保证。

## 异常终止时钟：freeze-v1

保存比赛、当前回合、播放、已进行时长及双方断线窗口剩余值；重启按最后可靠快照恢复，不把停服墙钟时间计入比赛。正常运行中的数据库等待不重置既有期限。保存后、崩溃前尚未持久的时钟推进可能回退到最后快照，这是明确的freeze-v1口径，不能当作精确崩溃时刻。

原本已断线的玩家保留原窗口剩余时间；崩溃时在线的玩家按原规则获得60秒服务器连接丢失窗口。重入仍校验本人、账号状态、会话、原冻结阵容和窗口；不能用当前阵容或默认配置替换原局。已接受出手恢复原seq/revision及回执，重放只返回原确认。

## 旧记录、过期与回收

| 情况 | 实际处理 |
|---|---|
| 旧账号playing记录没有head | 启动报告 `legacy-checkpoint-missing`、总数及最多20个matchId样本；本人入口明确unavailable，保留参与历史，不伪造RNG/局面。 |
| 不兼容format/engine、checksum损坏 | 报告 `incompatible-checkpoint` 或 `corrupt-checkpoint`，保留原数据并阻止该局安装。 |
| 临时SQL或文件访问失败 | 报告稳定错误码并重试；不会永久归类为版本不兼容。 |
| 最后可靠运行快照超过24小时 | 在持有权下生成原server-fault/winner=-1作废结果，保留原seq/动作数/配置；经NET-04处理，无虚构胜方。 |
| 已完整结算的恢复缓存超过7天 | 同日志域有界删除head与快照；原matches、参与者、outcome、奖励和账本保留。 |
| 仅预留未开局且已abandoned超过7天 | 只允许ordinal0/seq0、没有推进/结果的初始缓存回收；参赛历史保留，已有出手的关闭记录不满足此条件。 |

数据维护孤立引用目录新增checkpoint-head/checkpoint-match，共18类检查，不自动修复。触发器只允许符合上述结算/未开局证明的无head快照删除；不能直接删除未结算局来“修复”异常。

## 运维交接与回退

先部署前向迁移和兼容代码，再开放新账号局。数据与日志卷一起备份，目录仅服务账号可读写；日志含内部RNG与用户关联，禁止公开静态托管或写入Git。启动报告包含数量/稳定错误码及matchId，不含凭据或完整快照。

恢复失败先保留数据库、原日志、storage.json和quarantine；检查是否挂载原卷、数据库可达、engine/配置归档一致，再修复基础设施并重启/重试。来源冲突不得覆盖权威结果，按 [数据维护手册](data-maintenance.md) 先只读核验。blocked项在该进程内不反复导入，修复后以新进程重新校验。NET-03接口在接管前报告unavailable，不暗中开新局。

紧急回退先停新局并排空/冻结运行局，备份原数据库与日志，部署可读取当前快照/结果的兼容版本。不能切回仅游客恢复代码继续接管账号局，不能清空日志卷或向下迁移删除未结算历史。migration down仅供空的隔离测试库；不修改已确认物理、经济或3分钟/20秒/60秒玩法规则。
