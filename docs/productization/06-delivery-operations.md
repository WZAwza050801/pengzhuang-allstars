# 管理后台、质量与持续维护

## 1. 管理后台范围

| 模块 | 最低能力 | 权限与证据 |
|---|---|---|
| 用户 | 搜索/分页、账号状态、设备会话、封禁/解封、注销进度 | 支持人员只看必要信息；封禁写理由/期限/审计 |
| 战绩/对局 | 按用户或 matchId 查参与者、版本、结果、断线/结算状态 | 不展示 seatToken/RNG/敏感认证数据 |
| 资产与补偿 | 查账本、待结算、按业务事件补偿、幂等防重 | 财务/资产权限单列；高风险动作双人或审批策略由 ADR 明确 |
| 公告/邮件/任务 | 草稿、预览、目标人群、期限、发布与撤回 | 防重复发奖，受众与奖励规则版本化 |
| 数值/资源配置 | 上传已校验包、diff、灰度、回滚 | 禁止直接编辑进行中的比赛状态 |
| 维护与反馈 | 停新局、恢复入口、反馈工单状态、异常概览 | 不提供任意 SQL/远程 shell 给普通管理员 |

管理员登录与玩家账号明确区分授权；可复用 identity 但必须 RBAC/会话策略独立。管理员启用 MFA、短会话和敏感动作重新认证；所有后端 admin 路由均校验，不能靠隐藏菜单隔离。

## 2. 环境与配置

local、test、staging、production 使用相同构建路径、不同配置和凭证。开发可使用 Mailpit 等本地邮件服务；生产邮件/微信/存储 provider 必须是真实可验证实现，禁用 dev bypass。

配置 schema 至少：NODE_ENV、PORT、PUBLIC_ORIGIN、数据库 DSN、SESSION/签名键标识、Cookie/CORS、微信 appId/secret 引用、邮件 provider、资源 origin/manifestVersion、日志级别、指标端口、发布版本、实例 ID、支持协议/配置版本。

启动即校验：生产 HTTPS origin、禁止默认弱密钥、必填外部渠道凭证、非法端口/URL、DB schema 版本。只打印字段名和错误，不打印秘密值。`.env.example` 仅示例；production secrets 由部署平台注入。

Compose 本地包含 PostgreSQL、应用、可选 Mailpit/监控；镜像固定版本/摘要，非 root 运行，持久卷与备份边界明确。迁移用一次性 job，不能多实例启动时同时执行 DDL。

## 3. 可观测性

- 结构化日志字段：time、level、service、buildSha、instanceId、requestId、userId 的受控标识、matchId、seq、event、durationMs、errorCode。
- 禁止日志：密码、邮箱验证原 token、access/refresh/seat token、完整微信 code/secret。异常堆栈可在受控后端保留，返回用户只给 requestId。
- 指标：登录成功率/耗时、API p95/错误、匹配等待/取消、房间数、出手耗时、事件循环延迟、连接/重连成功率、快照失败、待结算积压、重复结算冲突、钱包不变量、资源加载失败。
- 指标 label 禁止 userId/matchId 等高基数值；这些放日志或 trace。
- `/healthz` 存活、`/readyz` 是否可接新流量、内部 `/metrics` 分离；维护/迁移/DB 不可用应影响 readiness，不因 alive 还返回 200 就继续接新局。

初始服务目标（待 QA-04 测量确认）：业务 API p95 <300 ms（不计第三方调用）；单杆裁定 p95 <150 ms；对局相关错误率 <1%；月可用性目标 99.5%。指标要附负载、硬件、区域和采样窗口，不能作为已达成承诺。

告警需要阈值、持续时间、去重、负责人、处置链接和恢复条件。用户未配置通知渠道时可本地展示/测试接收端验证，不擅自向真实 Slack/邮件发送消息。

## 4. 持久化与备份

1. 修正当前文件备份目录为默认及配置后的 ROOM_STORE_DIR，递归纳入正确范围，排除日志/临时文件/长期凭证泄漏。
2. 生产业务 PostgreSQL：每日全量备份 + 按目标 RPO 配置 WAL/PITR 或等价托管能力，异地存储、加密、保留与删除策略。
3. 初始目标：RPO 15 分钟、RTO 60 分钟；是设计预算，OPS-03/QA-05 以隔离恢复实测确认。预算不够需记录差距和发布范围。
4. 房间快照/事件与结算 outbox 都要有恢复策略；不能认为数据库备份自动包含本地 JSON 房间。
5. 验证备份 checksum 与 schema/配置兼容；在新数据库/目录恢复后跑账号、阵容、未结算恢复、账本总账检查。只生成备份文件不算完成。
6. 恢复演练不覆盖生产、不使用真实身份材料做公开样例；操作手册包含停止写入、恢复、验证、切流、回退。

## 5. 发布与维护

流水线：锁文件安装 → 文档/任务校验 → 类型/静态检查 → 相关测试 → 构建 → 资源 manifest 校验 → 依赖/秘密扫描 → staging → 契约/浏览器冒烟 → 产物签名/归档 → 按授权发布。

数据库变更使用 expand/contract：先加兼容字段/索引 → 兼容代码 → 回填验证 → 新代码 → 观察 → 后续移除旧字段。回滚应用前确认 schema 是否仍兼容；不要盲目 down 删除新用户数据。

维护流程：公告 → 停新匹配/新房间 → 现有房间 drain 或持久化接管 → 迁移/发布 → readiness/恢复检查 → 新建小流量房间 → 恢复入口。数据库临时不可用时不伪造发奖成功。

版本策略：应用 buildSha、协议版本、数据/资源版本、DB migration 版本分别记录。前端 HTML no-cache，带哈希资源 immutable；旧客户端明确更新提示和兼容窗口，不能在对局中途强刷。

生产公开发布、商店提交和付费服务按本轮授权执行；规划任务的存在本身不构成执行这些外部动作的授权。先完成构建、验证和可复查材料，再处理最终发布步骤。

## 6. 标准验证命令

当前已有：typecheck、build、test:physics、test:net、test:e2e。规划新增如下；首次创建相应功能测试时添加真实脚本，不放 `echo PASS` 或空测试占位。

| 命令 | 应由任务创建 / 内容 |
|---|---|
| `node tools/check-plan.mjs` | 本规划提供；ID、依赖 DAG、完成证据、本地链接 |
| `npm run check` | FND-05；类型、lint、清单和配置静态验证 |
| `npm run test:unit` | FND-05 初始化；新纯业务/状态机，用例随任务增加 |
| `npm run test:integration` | ARC-04/DAT；真实 PostgreSQL 事务、并发、迁移 |
| `npm run test:contract` | ARC-02；schema、HTTP/WebSocket 兼容与错误码 |
| `npm run test:field` | FLD；坐标/边界/皮肤锚点加现有 physics 回归 |
| `npm run test:balance` | BAL；固定数据实验，长实验可单独触发，不每次文案提交都跑 |
| `npm run test:e2e:web` | WEB/QA；登录到结算、错误恢复、视口矩阵 |
| `npm run test:e2e:online` | NET；自启服务并等待 ready、双客户端、独立端口、清理进程 |
| `npm run test:load` | QA-04；有场景/seed/并发/时长/阈值的 k6 |
| `npm run test:wechat` | WX；可自动部分 + 真机报告校验，缺凭证/设备必须失败或明确未验收 |
| `npm run test:app` | APP；平台构建/自动测试 + 签名/真机报告，不能仅 mock 原生桥 |

测试脚本要自管理端口/临时目录/服务进程，失败退出非零。核心场景不允许 SKIP 后总通过；平台不可执行在任务记录标阻塞。CI 使用独立数据库和迁移，禁止连接生产。

## 7. 必测失败与竞态

| 范围 | 场景 |
|---|---|
| 登录 | 枚举/暴力尝试、过期/撤销 token、并发 refresh、绑定冲突、找回重放、CSRF/CORS |
| 资产 | 他人 ownedCardId、重复升级、余额不足、revision 冲突、DB 事务失败、跨请求幂等键误用 |
| 对战 | 过期 turn/seq/config、重复 shot、超大消息、伪造身份、认输与出手竞态、双端登录 |
| 恢复 | 页面刷新、杀进程、断 Wi-Fi/切蜂窝、服务重启、DB 暂不可用、旧配置恢复 |
| 结算 | 写 outcome 后崩溃、发奖前/中/后崩溃、广播失败、消费者重复、不同结果冲突 |
| 匹配 | cancel 与 matched 同时、重复排队、服务重启、一个人占多场、版本不兼容 |
| UI | 加载/空/错/维护、超时返回、快速切页、重复点击、后台输入取消、监听器泄漏 |
| 运维 | 备份损坏、磁盘满、进程终止、迁移失败、发布回滚、drain 中新建房被拒 |

不要为了覆盖率写镜像实现测试；优先检验这些可观察行为与不变量。

## 8. 容量与扩展

分阶段测试：单局成本 → 10/50/100 间房阶梯 → 长稳态 → 突发/断线风暴；规模是初始实验梯度，不是容量承诺。记录硬件、Node 版本、配置、平均每分钟出手、包大小、CPU/内存、事件循环、DB 锁等待、错误与 p95。

若单进程不达预算：先拆同步写盘/CPU 模拟工作，保留房间串行状态；再按 Colyseus 版本配置多进程 presence、房间路由和唯一房间码；Redis 只存可恢复的协调状态，资产仍在 PostgreSQL。每种扩容都验证重连路由、进程死亡和配置冻结。
