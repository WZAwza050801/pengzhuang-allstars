# 数值系统、经济与对战平衡

## 1. 数据层次

1. 静态定义：球员身份/位置/稀有度、技能、阵型、场地、升级表。
2. 用户状态：持有卡、实际等级/经验、货币、已选阵容、赛季积分。
3. 单局快照：模式、双方等级、属性、随机状态、技能状态、规则/经济版本。
4. 表现状态：预测线、特效、音量、画质，不改变权威属性。

禁止将“面板属性点”“物理单位”“战力展示”“排位分”合并成一个数。金币/钻石的 UI 占位不能算经济系统。

## 2. 当前规则与映射基线

默认：5v5；比赛 180 秒；先进 3 球；回合 20 秒；断线 60 秒；等级 1–10、统一等级模式 Lv5；技能等级解锁 1/4/7；状态差默认关闭。当前 117 名运行时球员中，106 名有原等级表，另 11 名重建数据必须保留来源标记，不虚称同等原始资料精度。

```ts
// 当前 attrmap-1 语义；BAL-01/02 以实际数据和测试核对后冻结。
const normalized = Math.max(0, Math.min(1, (attributePoints - 21) / (119 - 21)));
const massMultiplier = 0.85 + normalized * (1.25 - 0.85); // weight
const speedMultiplier = 0.92 + normalized * (1.08 - 0.92); // power
const curveMultiplier = 0.60 + normalized * (1.40 - 0.60); // radian
const aimFraction = 0.45 + normalized * (1.00 - 0.45); // precision
```

上面是单个属性各自归一后的示意，不能拿同一个 normalized 同时代表所有属性。weight 不是 kg，radian 不是角度，precision 不是命中率。心理属性仅影响已开启的状态模式，不能擅自转成额外随机命中率。

出手速度保留正式函数：`v = vmax * speedMultiplier * power^gamma`；当前 vmax=9.1956、gamma=0.623、minPower=0.06。当前弧线角速度 1.98 rad/s、最大转角 103.354°。参数来自当前配置，不能从过期说明恢复为旧值。

## 3. 数值配置工程化

每套配置包含 schemaVersion、contentVersion、hash、sourceType、effectiveAt、关联测试报告。把规则、球场、物理、球员、技能、等级、属性映射、经济纳入可验证发布包。

- 导入校验：ID 唯一、引用存在、全部等级完整、合法范围、无 NaN/Infinity、概率 0–1、整数成本非负。
- 修改属性域或倍率要输出所有卡/等级的前后 diff，不用静默 clamp 掩盖异常导入。
- 单局冻结版本；服务器配置热更不能改变正在进行中的碰撞/奖励口径。
- 历史回放带配置 hash；旧版本保留策略明确。新增字段带默认/迁移；删除字段先做兼容窗口。
- 经济配置在 UI 只展示服务端报价，实际升级时再校验版本与余额。

## 4. 技能时序

保留正式 trigger：preturn、onShot、defense、passive；枚举所有 effect，并建立“触发 → 应用 → 播放 → 递减 → 失效”表。

每个技能定义：技能 ID、适用对象、解锁等级、技能等级概率、叠加规则、持续回合口径、优先级、互斥、耗时/动画、日志事件。离场和冻结倒计时按**所属方回合**，不能在渲染 tick 中递减。

至少覆盖：同杆多目标命中、已离场目标、冻结+锚定、连续额外行动上限、进球重置、超时跳过、认输、重连、结算后不再触发。概率测试用固定随机种子与置信区间，不要求短样本恰好等于期望。

回放只播放已裁定技能事件，不能客户端再抽一次随机。在线进行中不泄露服务端 RNG 状态。

## 5. 公平模式与排位

- **练习**：可自由试卡/等级，不产出正式排位奖励。离线练习不上传可信胜负。
- **好友约战**：初始默认统一 Lv5，可在明确房间规则下选择持有卡模式；双方看到相同规则摘要。
- **排位**：初始推荐统一等级、使用合法持有卡与固定技能规则；最终通过 ADR-0003 和 BAL-06 验证。不能把“等级公平”当成所有卡强度相等。
- **成长赛事**：采用真实持有等级、分组或战力约束，不能和统一等级榜混算。

匹配按模式、配置兼容、区域/延迟、积分段排队；等待变长时逐步扩大范围。禁止无提示用机器人冒充真人。断线/认输/双离线/服务器故障分别确定结果和奖励策略。

## 6. 成长与经济

BAL-05 输出 economy.json schema 和首个可调参数包，DAT-04/LIV 实现服务端规则。下面是**非付费测试参数建议**，在有报告前不是已批准的最终经济：

- 初始卡：给可组成完整合法阵容的固定集合；一次性创建，以 grantId 防重发。
- 初始升级模型：`cost(L→L+1) = roundToInteger(base * growth^(L-1))`；base/growth/maxLevel 为配置，不在界面硬编码。先模拟 7/30 天进度再定具体参数。
- 胜/平/负奖励分开配置；按活跃行为与每日上限限制刷取，不直接按客户端在线时长发奖。
- 任务/邮件/成就奖励全部进入统一账本，领取是事务；客户端点击两次不重复发放。
- 卡牌重复如何处理、是否允许同定义多实例、升级是否消耗重复卡，必须写明确规则再建约束；默认单用户同定义一张卡，重复获得转为可审计碎片。
- 金币与碎片默认可用；钻石 UI 在非付费版隐藏或明确不可购买，不制造可消费但无来源的假余额。
- 初始不做现金交易、玩家交易或付费抽卡；若用户决定引入，另做价格/概率/支付/退款/渠道审查，不能“顺手”加随机付费功能。

经济健康指标：每活跃用户净产出、各来源与消耗占比、达到关键等级的时间分布、重复卡转化、异常重复领取、余额负值次数、奖励失败待处理数。报表不收集不必要身份明文。

## 7. 可复现实验

固定 seeds、双方阵容、先手交换、模式、配置版本、AI 决策预算、执行环境；每份报告保存原始 CSV/JSON 和摘要。

| 实验 | 初始样本/目标 |
|---|---|
| 几何/物理回归 | 现有边界场景 + 至少 240 固定随机出手；不降低现有通过条件 |
| 属性单调性 | 有原表的所有卡×等级验证映射；区分数据本身非单调与映射错误 |
| 技能稳定性 | 各技能组合、不同回合结束路径；概率用足量试验给误差范围 |
| 先后手偏差 | 至少 1000 场同阵容配对，交换先手；记录置信区间，初始目标胜率偏移不超过 5 个百分点 |
| 卡组强度 | 位置/稀有度/技能分组对阵；明确 AI 代理的偏差，不当作真人平衡结论 |
| AI 难度与耗时 | 固定设备记录 p50/p95/max 决策时长和胜率；难度有可辨识差异 |
| 成长速度 | 7/30 天多活跃度模拟，明确目标并输出敏感性分析 |

初始目标需要实测后调整，不能为了满足表格把服务器判定改成偏袒某一方。失败先定位数据、规则、AI 或样本问题；调整有版本和差异报告。

## 8. 配置发布与回滚

配置先导入 staging → schema/引用校验 → 物理/技能/经济回归 → 差异报告 → 小范围新局 → 指标观察 → 扩大。维护后台只发布已签名/哈希验证的完整配置，不编辑线上正在进行中的单条球员属性。

回滚指向已验证版本，新局切回；旧局继续原版本或按明确维护策略终止与补偿。涉及账号成长迁移时，代码回滚不等于数据库/资产回滚；账本使用纠正记录，不删旧流水伪造历史。
