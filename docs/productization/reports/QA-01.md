# QA-01 · 测试运行隔离

基础测试现在不依赖固定的 2567/4173 端口。只有 `APP_ENV=test` 可以使用 `PORT=0`：游戏服务随后通过 `server_started` JSON 事件把系统实际分配的端口交给 E2E；静态服务也绑定临时端口。local、staging 和 production 仍拒绝端口 0。

`tools/e2e-browser.mjs` 为每次运行创建独立房间存储，等待健康检查和子服务退出，并把截图与模式诊断写入忽略的 `work/e2e-artifacts`。可通过 `E2E_ARTIFACT_DIR` 指定其他临时目录，不再覆盖已跟踪的验收截图或报告。

`npm run test:qa` 先构建，然后执行两轮：

- 每轮运行单元测试和契约测试；
- 同时运行两个独立 Chromium E2E 实例，验证端口和临时存储相互隔离；
- 保留一个 Web 端口，确认 E2E 非零失败，且结束后没有新增 `allstars-e2e-*` 临时目录。

本机实测 `npm run test:qa` 通过两轮；单独 E2E 为 18 PASS / 0 SKIP / 0 FAIL。`npm run typecheck`、`npm run lint` 与 `npm run build` 也通过。`.github/workflows/ci.yml` 使用 Node 24.22.1，安装 Chromium，执行 `npm run check` 和同一 `test:qa` 入口；远端 CI 尚待 GitHub 触发，不以本地结果替代。

真实 PostgreSQL integration、Safari/真机和微信/App 矩阵不在这个任务的完成声明内，分别由 ACC-01/QA-02、QA-03、AST-06、APP/WX 后续任务验收。
