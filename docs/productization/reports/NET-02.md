# NET-02 · 版本化对战与出手去重

2026-11-18；Windows / Node 24.22.1 / npm 11.9.0 / 隔离 PostgreSQL 17.12 / Chromium。任务验收完成。本轮全部使用本地临时服务，没有使用远端服务器。

实现定义见 [match-protocol.md](../../engineering/match-protocol.md)。账号协议 2 与游客协议 1 分开，数据库绑定票据版本并拒绝旧账号票据；HTTP 不支持版本明确提示刷新。已有房间仍深冻结原 GameData/ModeRules，不更改物理、场地或经济。

回执按 match/user/shot 区分并比较规范化完整载荷。同一重试回原 seq/acceptedRevision；修改输入、turn、revision 或配置返回 shot-conflict。真实 PostgreSQL 与 SDK 验证同名账号区分、相同 shotId 在不同账号各自接受、替换连接后仍查原回执、比赛结束后仍可查。v1 保持 duplicate-shot+seq；新游客记录附哈希并在服务器重启后识别冲突，缺哈希旧记录继续兼容。

真实共享物理通过可控延迟端口验证：出手先于排队认输提交；旧回合定时器不跳过新回合；预猜下一回合的排队出手拒绝；比赛计时按队列在回放后结束；窗口过期不因计算积压而延长；销毁后迟到计算不提交。计算抛错、超帧、超字节和非法坐标均不改变原局面/回执，同一意图随后可成功。结果提交后投递故障仍保存回执，跨测试服务器重启后返回原序号。恢复夹具使用内存 RoomStore 保留真实 record、codec 和服务器重建，不冒充生产数据库恢复。

独立客户端状态测试覆盖重复/乱序回放、终局后旧消息、旧 resume/error 不解除 pending、缺回放 ACK 只触发同步、协议/帧不兼容关闭。传输入包 2048 bytes，出包 512 KiB 保守 UTF-8 JSON 上界；最多 1024 帧且受冻结模拟时长限制、65 实体和 4096 项事件边界；不截断物理轨迹。
