真实 SMTP 注册/验证/登录回到 `/lineup`，读取当前用户的持有卡和金币。键盘选中位置再放卡，交换已上阵的卡，双击保存只发一个 PUT；请求只有五个 ownedCardId 和 expectedRevision，数据库顺序/新 revision 与页面草稿一致。清空位置后不能保存，提示草稿待保存；职业仍可跨槽，没有引入职业硬绑定。筛选无结果、五槽空位、停用卡、客户端缺少定义均有明确状态。

真实服务器并发保存造成 409 时，展示服务器顺序并保留用户草稿；用户选择保留草稿并采用新 revision 后才再保存。保存成功后丢弃响应，同时中断确认 GET，页面保留待确认草稿；再确认只读 GET，最终数据库正确，只有一次原 PUT。将他人卡 UUID 注入实际保存请求被拒绝，数据库未变；在加载后把本人卡停用，再保存被真实服务拒绝并重新读取停用状态。普通客户端没有设置卡状态的入口，停用写入仅为隔离 fixture。

升级显示服务端报价。双击后主动丢失已提交响应，页面记录原意图；刷新页面再确认，key/body 完全相同，真实数据库只一条升级回执、扣 100 金币、目标卡只到 Lv2。重放后重新读当前库存，不拿历史回执覆盖新余额。服务端先扣至 50 后旧页面点击升级，拒绝透支并提示余额不足；余额变化由隔离测试中的受信资产端口产生。并发外部升级使卡 revision 变化，旧报价请求 409，没有第二次扣款，页面读取下一报价。

跨账号时原账号未确认升级继续保留，新账号没有继承该意图且能独立升级。额外真实 HTTP 测试带错误 X-Account-Id，返回 ACCOUNT_CHANGED，操作 key 尚未绑定、余额不变；正确账号随后用该 key 只成功一次。客户端新会话 CSRF 缓存与迟到响应隔离，有失败复现及回归单元测试。403/限流不抹掉可能已提交的旧意图，存储写入拒绝时不发送升级请求。

真实账号持有 25 张卡，浏览器把请求分页上限降至 2，让服务端真实返回多页；页面完整读取后以 12 张/页呈现，第三页只有 1 张，UUID 均属于该用户。旧导入偏好显式采用后仅变本地草稿，保存前云阵容不变，保存后按预期更新，金币仍 300。空库存/空预设及缺少客户端定义是明确的 HTTP 响应注入，用于检验 UI 失败/空态，未声称这些是生产账号的实际数据。

首轮浏览器测试发现隐式下拉标签的名称不稳定及跨账号旧 CSRF 缓存，分别补明确可访问名称、按会话/请求代失效缓存后通过。一次全量失败来自测试在“待确认按钮出现”时过早断言请求数，实际 CSRF 请求尚在等待；改为等待按钮真正可重试，保持原来的请求数、相同 key/body、数据库扣款/等级断言，最终 157 项全通过。
