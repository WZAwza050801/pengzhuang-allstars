# 消息与状态草案

所有消息通过已经认证的房间会话发送。协议字段见04目录data_contracts.ts；这里只列业务约定。不要照抄成某个Colyseus版本的API调用。

| 方向 | 消息 | 必要内容 | 服务器行为 |
|---|---|---|---|
| 客户端→服务器 | set_lineup | 5个cardId、sourceVersion、level | 验证存在、可选、数量与重复限制 |
| 客户端→服务器 | ready | ready布尔值 | 双方准备后锁定配置，创建对局 |
| 客户端→服务器 | shot | matchId、turnId、clientShotId、playerId、方向、力度、弧线、configVersion | 验证、去重、接受或拒绝 |
| 服务器→客户端 | shot_result | 接受tick或拒绝原因、原clientShotId | 让发送方知道请求是否生效 |
| 服务器→客户端 | state | tick、phase、turnId、行动方、10枚棋子和球、比分、版本 | 加入／重连给完整状态；运行时可发送增量 |
| 服务器→客户端 | match_event | eventId、tick、goal／skill／turn／finished、载荷 | 事件只播放一次；权威结果仍保存在state |
| 服务器→客户端 | reconnect_wait | 缺席座位、截止服务器时间 | 显示等待，禁止额外出手 |
| 客户端→服务器 | rematch | matchId、愿意再赛 | 双方同意后创建新matchId，清除上局出手去重记录 |

## 时间与版本

- tick是固定物理步序号；客户端的Date.now不能作为出手优先级。
- 倒计时以服务器deadline为准；客户端时钟偏差只影响显示估计，不能决定谁超时。
- rulesVersion、physicsVersion、rosterVersion在开局锁定。调参或重绘图可以开发时热加载，正式对局不能打一半换配置。
- 同一个matchId的旧turnId请求即使晚到，也要拒绝。被接受的出手ID应记录到该局结束，防止延迟重发造成重复动作。
- 消息大小、速率、字段形状与昵称长度均在运行时检查；TypeScript类型不会自动检查来自网络的JSON。

## 需要持久化的记录

| 记录 | 保存内容 | 原因 |
|---|---|---|
| 访客 | 随机身份标识、昵称、会话校验信息 | 刷新后仍认作同一位玩家；不把昵称当身份 |
| 阵容 | cardId、版本、等级、选择策略版本 | 防止更新数据后悄悄换人或换属性 |
| 对局 | matchId、双方、版本、开始结束、比分、结果原因 | 唯一结算与排错 |
| 回合日志 | turnId、输入、前状态、随机结果、tick与哈希 | 可重复检查为什么出现某次碰撞或进球 |
| 检查点 | 完整可重建的停稳世界、技能状态、下次行动方 | 重连／重启从一个清楚的位置继续 |

不会在比赛状态里广播会话密钥或重连令牌。私人房间号只负责定位房间，不能据此冒用现有座位。
