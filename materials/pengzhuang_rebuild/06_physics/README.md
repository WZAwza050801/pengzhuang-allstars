# 把“手感”变成几杆可以反复比较的球

目标不是让你反复拖动几十个摩擦滑块，而是让开发AI自动打同一批球：半力空场走多远、碰墙弹多远、重棋子撞轻棋子会怎样。每改一组参数，就跑完样例并给出轨迹差异，留下最接近目标的一组。

## 已知与未知

| 已有依据 | 没有恢复的内容 |
|---|---|
| 原版五属性和成长表 | 属性点到质量、初速度、曲率和随机误差的公式 |
| 弧线存在 | 作用于棋子还是足球、弯曲持续条件、原手势 |
| 完全球过线 | 门柱精确碰撞几何与不同时期球场比例 |
| 技能参数、条件和文案 | 全部枚举的执行函数、内部回合计数与随机流程 |
| 静态球场与阵型坐标 | 实际世界单位、区域坐标换算与动态位移 |

所以，这份方案可以显著减少反复手调，却不能保证“零调参”或“精确等于原版”。没有动态参考时，先自动拟合明示的复刻手感；有实况以后再替换目标，尽量不改玩法代码。

## 计算只写一份

采用独立的Planck.js世界，重力为0，球员与球是圆形刚体，边界与门柱是明确几何。Planck基于Box2D，可用于浏览器和Node；官方文档说明固定时间步及bullet连续碰撞检测。来源为项目官方文档，2026-11-14查阅：[项目](https://piqnt.com/)、[固定步进](https://piqnt.dev/planck.js/docs/world/simulation.html)、[高速碰撞](https://piqnt.dev/planck.js/docs/body.html)。

项目如何使用是本次建议：

- 服务器固定步进起步120Hz；显示30／60／120FPS时不改变一次模拟计算。不要把渲染delta直接塞进物理。
- 动态圆盘与足球都要测试高速穿透。根据最高速与最小半径决定bullet设置和最大速度；启用CCD后仍要跑门柱、对撞和窄缝样例，不能把它当作无需验证的保证。
- 俯视球场的减速主要是沿速度反向的地面阻力；接触面的friction不能直接代替空场滑行摩擦。建议先用可测的恒定减速及停稳阈值，再比较线性阻尼是否更贴近参考，避免同时堆很多阻力项。
- 空场目标可用`距离≈初速度²/(2×减速度)`、`停下时间≈初速度/减速度`给初猜，再让真实模拟验证；该公式只针对恒定减速且没有碰撞，不是原版公式。
- 所有物体低于速度阈值并连续维持一小段时间才结算。最大运动时间触发时要记录超时诊断，不无声地把还在移动的棋子停住并当成正常结果。
- 进球看整个圆穿过门线且穿过球门有效开口；使用前后位置的扫掠判断，避免高速跨过触发区漏判。门柱碰撞与球门装饰分开。

## 先校准什么，后校准什么

| 阶段 | 自动打的球 | 主要调整项 | 暂时固定 |
|---|---|---|---|
| 几何 | 场边／门柱／边线可视叠加，极端角度入门 | 有效球场、半径、门线与开口 | 属性、技能、随机数 |
| 空场 | 同一棋子25%、50%、100%力度 | 力度到初速度曲线、地面减速度 | 统一基准属性 |
| 碰撞 | 正面、斜碰、墙反弹、球门柱、高速相撞 | 质量比、恢复系数、CCD／步长 | 力度与阻力已选结果 |
| 属性 | 只改变一种原属性的对照样例 | 属性点到模拟参数的单调映射 | 其他属性与技能 |
| 弧线 | 左右对称、零弧线、连续触球 | 弯曲强度与触发范围 | 明示采用哪种复刻解释 |
| 技能 | 条件满足与不满足、持续和叠加 | 事件时序、效果、计数 | 基础物理与随机种子 |

一次把所有未知参数一起搜索，会出现多组参数互相抵消，轨迹差不多却完全不能解释。分阶段把这些歧义减少，最终保留能复现样例的少量参数。

## 自动校准应交付的东西

`runCalibration`必须直接调用正式模拟，读`calibration_targets.json`，用固定随机种子生成候选参数；先粗搜索，再缩小范围。分离拟合样例与保留样例，不能只在用于选参的几杆上报好成绩。

输出`physics.best.json`、`calibration_report.json`、可视轨迹叠加、失败样例与采用的目标版本。报告每杆距离误差、停稳时间误差、反弹轨迹误差、是否进球，说明权重和容差。校准应能用一条命令重跑；需要人决定时展示3个候选手感的短回放，而不是要求理解几十个物理常数。

自动化验收至少200杆固定种子场景，覆盖角落、门柱、满力、重轻对撞与接近停稳。200是本次验收规模，不是统计精度保证；没有运行报告就不能声称本包已通过。

## 属性映射先保持简单

- weight先只影响棋子相对质量；power先只影响发射速度或冲量。选哪种会影响大体重球员的出杆关系，必须以成对样例比较后记录。
- radian只接入明示的复刻弧线公式，不直接作为角度。
- mind、precision在作用机制未知时先显示源值，开发版标为待接入。需要临时规则就放`rules.json`并标出“复刻设定”，不能偷偷凭空加命中率或瞄准抖动。
- 技能由条件事件驱动；duration在枚举语义确认前保持原值，不乘成秒数。triggerPerList保留列表，不能把每项概率直接相乘。

需要动态参考时，开发AI负责整理`reference_measurements.csv`，逐杆记录版本、视频来源、开始／停止帧、画面比例、力度是否可见与误差范围。现在没有已经测量好的原版运动轨迹，这个文件随包提供的是空表头。
